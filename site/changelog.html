Changelog

Every Vect release, what changed, and how to upgrade. Versions use three-part numbering. Nothing ships until its full test suite passes byte-identical output checks.

0.2.4 — in development, releases next

The polish release: closes real gaps found while writing programs, and lays the last pieces 0.2.5's Vect-written lexer needs.

Zero-argument target calls

Calling a function that takes no arguments through target notation finally works. Before 0.2.4 only (result.add 25, 75) (with args) and bare main() worked — (r.boom) died with "Undefined variable". Now all three call forms work everywhere:

vectfn boom
    v42
    rtn v
vectfn main
    (r.boom)
    echo r          cmt 42
main()

String escapes

String literals now process \n (newline), \t (tab), \r, \\, \" and \0. Unknown escapes (like \x) stay literal so old programs can't break silently:

echo "line1\nline2"

clock timing primitive

(t.clock) returns integer milliseconds since the VM started. Built for honest benchmarking — wrap any block and subtract:

(t0.clock)
lo1000
    (x.x+1)
(t1.clock)
(elapsed.t1 - t0)
echo elapsed

chr primitive

(s.chr 65) builds the one-character string "A" from a code — the missing inverse of (c.char s, i). Codes 0–255; anything else halts with a line number. This is the last primitive the 0.2.5 Vect lexer needs to build tokens character by character.

Embedded key-value store

A tiny NoSQL store for scripts: typed string/int/float values persisted to a length-prefixed text file (S4:name4:vect — readable and debuggable by hand):

kvopen db, "saves.kv"   cmt missing file starts empty
kvset db, "name", "vect"
kvset db, "score", 99
kvsave db
kvclose db
kvopen db2, "saves.kv"
(n.kvget db2, "name")
(ok.kvexists db2, "missing")  cmt 0 when absent
kvdel db2, "score"
kvclose db2

Rules: reading a missing key halts (check kvexists first), deleting a missing key is a silent no-op, arrays cannot be stored, and kvclose discards unsaved changes — call kvsave first.

vectc --help

Prints usage, the three run modes and the docs URL. --version (added in 0.2.3) now reports vectc 0.2.4.

Upgrading from 0.2.3

Fully backward compatible — every 0.2.3 program runs unchanged. New capabilities only: escapes activate automatically in old string literals (only affects strings that already contained backslashes), and chr/clock/kv* are new reserved words in target expressions, so rename any user function called clock, chr, len, cat, cmp, char or get before upgrading (the compiler will tell you with a clear error if you forget).

0.2.3 — current

The expressiveness release: the two biggest spec gaps closed, plus error quality and distribution.

Floats

Compact float assignment (y3.14), float literals in expressions, and int↔float promotion across all five arithmetic ops and all six comparisons. Integer-only programs behave exactly as before (including truncating /); any float operand switches that operation to float. sqrt of a float returns a float; sqrt of an int still returns an int.

y3.14
(r.y*2)      cmt 6.28
a10
(m.a+y)      cmt 13.14

String operations

FormDoes
(n.len s)Byte length of a string, item count of an array
(c.char s, i)Byte code at index (bounds-checked)
(ok.cmp a, b)String ordering: -1 / 0 / 1
(out.cat a, b)Concatenation; numbers auto-convert

Strings also compare with all six comparison operators in if conditions (if msg == msg). Mixing strings with numbers in a comparison halts with a clear error instead of guessing.

Filenames in errors

Runtime faults inside .vth libraries now name the file: at line 4 (mylib.vth). Errors in the main file keep the classic short format. Compile-time errors in headers name the header too.

Distribution

--version flag, Scoop alias vect alongside vectc, VS Code extension v0.2.3, documentation split into four chapters, VirusTotal-verified release zip with published hash.

Upgrading from 0.2.1

Backward compatible, with two notes: float-looking trailing text like y3.14 previously errored and now assigns (nothing working changed meaning), and string-vs-number comparisons that used to attempt numeric parsing now halt — almost always a latent bug being surfaced, but check any program comparing user input with ==.

0.2.2

Intentionally skipped — its scope shipped as 0.2.3 instead. There is no 0.2.2 and there never will be; do not go looking for it. Package managers jump straight from 0.2.1 to 0.2.3.

0.2.1 — first public release

The foundation everything since is built on:

  • Bytecode compiler + stack VM replacing the original tree-walk interpreter — 33-op instruction set, per-function chunks, call frames, per-instruction line tracking, and a --dump disassembler.
  • Real stdout for echo/echow/VGA banners (errors stay on stderr per spec).
  • File primitives fopen/fread/fwrite/fclose with text and integer I/O.
  • Real .vth includes — directory-relative, nesting, loaded once, restricted to vectfn definitions.
  • if/els dual branches via a new jump op.
  • Scoop distribution with hash-pinned manifest, plus the static website with full reference docs.

Still downloadable as a zip for archival purposes, but Scoop serves 0.2.3+.

Pre-0.2.1

Internal development builds (0.1.x–0.2.0), including the original tree-walk interpreter era. Release status is under consideration — they are not published, not supported, and not recommended for any use. Anything you find labeled older than 0.2.1 should be treated as archaeology, not software.

How releases work

Every release follows the same drill so any version can be re-verified later: full test suite must pass byte-identical, release zip built with -O ReleaseFast, SHA-256 published in the Scoop manifest, independent VirusTotal scan linked from the download page, changelog entry written, version badges bumped across the site. If any step fails, the version does not ship.
