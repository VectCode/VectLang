Performance

Honest numbers only. Vect is a bytecode VM: scripting-language speed today, native compilation on the roadmap.

Measure it yourself

(t0.clock)
lo1000
    (x.x+1)
(t1.clock)
(elapsed.t1 - t0)
echo elapsed      cmt ms for 1000 loop iterations

Or from outside: Measure-Command { vect sieve.vt }. Don't trust any benchmark (including ours) without the program attached.

Writing fast Vect

  • Hoist loop invariants: compute (n.len s) once before the loop, not inside it.
  • Prefer ints over floats and cat-building big strings in hot loops (each cat allocates).
  • Use get/set on arrays instead of rebuilding strings as buffers.
  • Deep if nesting is free; deep call recursion is not (64 frames).

Roadmap

Native AOT compilation (0.3) removes the interpreter loop entirely — the same programs, machine code. Until then, this page is the whole truth.

Memory model (why it's shaped this way)

Three layers, each with its own budget — understanding them explains every limit above:

  • Slots — each function gets fixed variable cells (params first), allocated once per call. Variable access is a single array index: no dictionaries, no lookup cost, ever.
  • Operand stack — expression evaluation pushes/pops here (512 slots per frame). Deep expressions cost stack, not heap.
  • Arena — strings, arrays, and stores allocate from one arena freed at exit. No garbage collector pauses, no per-object bookkeeping — the price is that memory only grows within a run.

Practical reads: keep hot data in slots/arrays (cheap), avoid rebuilding big strings per iteration (each cat is a fresh allocation), and treat the 64-frame cap as a recursion budget, not a suggestion.

What "fast enough" means here

Vect optimizes for programs that finish before you notice: CLIs, small games, file tools, boot-time scripts. A 100-iteration game loop, a 25-prime sieve, a 100-line FizzBuzz — all sub-second with room to spare. If your program needs minutes of number-crunching, that's what the 0.3 native backend is for; write it in Vect anyway and recompile later.
