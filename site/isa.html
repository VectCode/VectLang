Bytecode ISA

What vectc --dump prints. Stack machine: operands in brackets are popped, results pushed. Slots are per-function variable cells.

Reading a dump

== add (chunk 0, arity 2, slots 3) ==
0000  load 0 0   ; line 7
0001  load 1 0   ; line 7
0002  add 0 0   ; line 7
0003  store 2 0   ; line 7

Each function compiles to a chunk: fixed slots (params first), operand stack per frame, every instruction tagged with its source line for error reports. Frames nest 64 deep; stacks hold 512 values.

Calling convention

  1. Caller pushes arguments left to right.
  2. call N pops exactly arity values into slots 0..arity-1 of a fresh frame (own slots, own stack).
  3. Callee runs; ret pops one value, drops the frame, pushes the value onto the caller's stack.
  4. Statement calls (main()) follow call with pop; value calls ((r.add 25, 75)) follow it with store.

There are no globals across frames by design — shared state travels through arguments, arrays (heap-indexed, so indices copy cheaply), files, or stores.

How errors map to bytecode

Every instruction carries its source line, so a fault deep in a loop still reports the exact line (and header file). Compile-time faults (unknown names, bad arity, bad blocks) fire during emission with the definition's line; runtime faults (div-zero, OOB, bad handles) fire mid-execution with the faulting instruction's line. Same format, same exit code — see the catalog.
