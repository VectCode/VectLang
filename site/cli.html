CLI reference (vect / vectc)

Both names run the same program (Scoop installs the vect alias).

Commands

CommandDoes
vect program.vtCompile to bytecode and run on the VM
vect --dump program.vtPrint disassembled chunks + const pool, don't run (see ISA)
vect --versionPrint version, e.g. vectc 0.2.4
vect --helpUsage, modes, docs URL

Exit codes

CodeMeaning
0Success (including --dump/--version)
1Runtime or compile error — details on stderr (see error catalog)
2Usage error (no file given)

Piping

echo 42 | vect program.vt      cmt feed stdin
vect program.vt > out.txt      cmt program output (stdout); errors still show (stderr)

Paths (source file, fopen paths, .vth includes) resolve relative to the working directory, except .vth which resolves relative to the file naming it.

Scripting with vect

Batch files that run many programs and stop on failure:

$files = @("a.vt", "b.vt", "c.vt")
foreach ($f in $files) {
    vect $f
    if ($LASTEXITCODE -ne 0) { echo "FAILED: $f"; break }
}

Because errors go to stderr and output to stdout, vect prog.vt > out.txt captures clean program output while failures still scream on screen. Check $LASTEXITCODE (0 ok, 1 error, 2 usage) after every run that matters.

Reading a dump

--dump prints one chunk per function plus the const pool. Each line is address op a b ; source line. Follow a call: call N jumps to chunk N, ret pushes the value back, the caller stores it. Full op list: ISA reference.

PatternSnippet
Fail fastvect build.vt; if ($LASTEXITCODE -ne 0) { exit 1 }
