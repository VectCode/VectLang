Style guide

How to write Vect that other humans enjoy reading. The compiler accepts more than this guide allows — these are conventions, not rules.

Names

  • Variables read best as words: score, paddleY, not s, py — compactness comes from the syntax, not from shortening names.
  • Remember trailing digits assign: a variable literally named var2 cannot be written plainly. Prefer letter names, or compute suffixes explicitly.
  • Functions are verbs: add, drawline. Never put a dot in a function name — dots separate the name from its parameters.

Math

  • One operation per target expression. (d.u-pick) then (d.d+3) beats clever nesting nobody can debug.
  • Spaces inside (target. expression) are free — use them: (ballX.ballX + ballDX).
  • Name intermediate results (distX, paddleBottom) instead of re-deriving them.

Control flow

  • Prefer early patterns over deep nesting: three levels max. Extract a vectfn instead of a fourth if.
  • loN for fixed work, loNw cond with a real condition — never lo1000w true without an exit flag inside.
  • Always pair if with els when the false path matters; silent no-ops hide bugs.

Defensive habits

  • Check kvexists before kvget; check ok flags after input.
  • Initialize every counter (i0) right before its loop — never reuse loop variables across loops.
  • One cmt per non-obvious block. If it took you a minute, it takes a reader ten.

Files

  • Header block first, always in the same order: vt.init, headers, (main), branch.
  • Shared code goes in .vth after its second use, not its first.
  • kvsave before kvclose — closing discards unsaved changes by design.

Anti-patterns (seen in the wild)

Don'tWhy / do instead
Single-letter everything (a b c x y)Compactness is the syntax's job. Name the idea: score lives turns.
Reusing one counter for two loopsStale values leak across loops. Fresh i0/j0 per loop, always.
(x.get arr, i) twice for the same cellRead once into a named temp; the second read is a second bounds check and a second chance to typo the index.
Giant mainOver ~40 lines, extract a vectfn. Test it alone with echo probes first.
Magic numbers (lo100, if x == 119)Name them: maxretries100, keyW119 with a cmt saying what 119 is.
lo1000w true with no exitEvery infinite loop needs a done flag set on all exit paths, or Ctrl+C is the UI.
