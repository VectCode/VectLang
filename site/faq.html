Frequently asked questions

Is Vect real? Can I run it today?

Yes. Install via Scoop, save any example into a .vt file, run vect file.vt. vect --dump shows the actual bytecode your program compiled to — a fake language couldn't do that.

Is it safe?

Every release zip is scanned by ~70 antivirus engines on VirusTotal before announcement, with the public report linked on the download page and SHA-256 hashes published for independent verification. Windows SmartScreen may still warn because the binary is unsigned (no publisher certificate yet) — that warning is about identity, not detected malware.

Is Vect open source?

No. Vect is proprietary: all rights reserved. Sources are visible on GitHub for transparency; the compiler binary is free to download and use under the TERMS.txt shipped in every release (no redistribution, no reverse-engineering, no resale).

Who makes Vect?

Designed and built solo by paraxapp — language, compiler, docs, releases, everything. Solo-built is the norm for young languages, and one head keeps the architecture coherent.

Windows only?

Today, yes (x64). A Linux build is planned for 0.2.6 — the compiler is written in Zig and cross-compiles cleanly; what remains is testing and packaging.

How fast is it?

It's a bytecode VM, not native code — expect scripting-language speed, honestly measured. Time anything yourself with the clock primitive (see the prime sieve), and don't trust any benchmark without a --dump next to it. Native compilation is the 0.3 milestone.

Why is the syntax so compact?

Density is the design goal: whole programs in a handful of lines, zero boilerplate. x10 reads as a typo on day one and as obvious on day three. If it feels alien, the 5-minute guide is the fastest way through.

Can I use Vect commercially?

Running your own programs: yes, that's what the free-use terms cover. Redistributing the compiler itself, embedding it in a product, or selling anything built on the toolchain: contact vectlang@proton.me first.

How do I report a bug?

Email vectlangsupport@proton.me with your .vt file, the command you ran, and the full error output. Minimal reproducers get fixed first.

How can I help?

Write programs and share them, report bugs with reproducers, improve docs understanding by asking questions, make videos. Code contributions to the compiler aren't accepted (proprietary), but great example programs may ship with the release.

Why Zig for the compiler?

Manual memory control with no hidden runtime, comptime for tables and parsing, and effortless cross-compilation (the Linux build is one flag). The whole toolchain is a single dependency-free binary — very on-brand for Vect.

Why proprietary, not open source?

Sustainability and coherence: one author, one architecture, no design-by-committee, with a commercial future. Sources stay visible on GitHub for trust; the binary is free to use. If that tradeoff bothers you, the docs, examples, and spec are free to learn from regardless.

Is Vect good for learning programming?

Surprisingly yes for a low-level language: the edit-run loop is instant, errors name file and line, and there are only ~50 bytecode ops to ever wonder about. Start with the 5-minute guide, then the Hangman tutorial.

Does Vect work offline?

Fully. One exe, no accounts, no phone-home, no package downloads. Your programs, stores, and headers are plain files on your disk.

Where is the community?

Blog comments on dev.to, videos on YouTube, and email for everything else. A real forum arrives when the crowd needs one.
